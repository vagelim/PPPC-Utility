# ![PPPC Utility logo][logo] Privacy Preferences Policy Control (PPPC) Utility

[logo]: /Resources/Assets.xcassets/AppIcon.appiconset/PPPC_Logo_32%402x.png "PPPC Utility"

PPPC Utility is a macOS (13.0 and newer) application for creating configuration profiles containing the Privacy Preferences Policy Control payload for macOS. The profiles can be saved locally, signed or unsigned. Profiles can also be uploaded directly to a Jamf Pro server.

All changes to the application are tracked in [the changelog](https://github.com/jamf/PPPC-Utility/blob/master/CHANGELOG.md).

## Installation

Download the latest version from [the Releases page](https://github.com/jamf/PPPC-Utility/releases).

## Upload to Jamf Pro

PPPC Utility can use bearer token authentication (or basic authentication as a fallback for versions of Jamf Pro older than v10.34) to any supported
Jamf Pro version using the username and password of a Jamf Pro user account.  The user account at minimum needs the two privileges indicated below.

Jamf Pro 10.49 and higher can use OAuth client credentials to access the API.  The client ID and client secret generated by Jamf Pro in the
"API Roles and clients" settings are used during the PPPC Utility upload process.  When setting up the API Role, these are the permissions that
PPPC Utility requires to upload the profiles.

#### Required API Permissions

- "Create macOS Configuration Profiles" - primary permission to upload profiles; each upload from PPPC Utility creates a new profile.
- "Read Activation Code" - needed to retrieve the organization name that is placed in the profile.

### Jamf Pro 10.7.1 and newer

Starting in Jamf Pro 10.7.1 the Privacy Preferences Policy Control Payload can be uploaded to the API without being signed before uploading.

![In 10.7.1 or greater choosing **Signing Identity** is optional before upload](/Images/UploadUnsigned.png "Upload unsigned")

### Jamf Pro 10.7.0 and below

To upload the Privacy Preferences Policy Control Payload to Jamf Pro 10.7.0 and below, the profile will need to be signed before uploading.

![In 10.7.0 or less **Signing Identity** must be chosen before uploading](/Images/UploadSigned.png "Upload signed")

## Command-line interface

Run the executable inside the app bundle with `--cli`.

```bash
PPPC="/Applications/PPPC Utility.app/Contents/MacOS/PPPC Utility"
"$PPPC" --cli help
"$PPPC" --cli inspect --app "/Applications/Example.app"
"$PPPC" --cli generate \
  --app "/Applications/Example.app" \
  --service Accessibility=Allow \
  --service SystemPolicyAllFiles=Allow \
  --identifier com.example.pppc --name "Example permissions" \
  --output ./example.mobileconfig
```

`inspect` returns JSON with the application identifier, display name, and designated code requirement.
For multiple applications or Apple Events rules, use a JSON configuration file:

```json
{
  "metadata": {
    "identifier": "com.example.pppc",
    "name": "Example permissions",
    "organization": "Example Organization"
  },
  "applications": [
    {
      "path": "/Applications/Example.app",
      "services": {
        "Accessibility": "Allow",
        "AppleEvents": "Allow"
      },
      "receiver": { "path": "/System/Applications/Mail.app" }
    }
  ]
}
```

```bash
"$PPPC" --cli generate --config ./permissions.json --output ./example.mobileconfig
"$PPPC" --cli modify --input ./example.mobileconfig \
  --config ./permissions.json --output ./updated.mobileconfig
"$PPPC" --cli identities
"$PPPC" --cli sign --input ./updated.mobileconfig \
  --output ./signed.mobileconfig --identity "Exact certificate name"
```

- Configuration entries accept either `path` or both `identifier` and `codeRequirement`.
- Metadata flags override configuration metadata. One `--app` with repeated `--service` flags can add an application to the configuration.
- Authorization values are `Allow`, `Deny`, and `AllowStandardUserToSetSystemService`. The CLI rejects values that the service does not support.
- For `modify`, use `Remove` to delete a rule. Explicit identifiers do not need a code requirement for removal.
- Apple Events rules require a `receiver` in the JSON configuration.
- `modify` requires exactly one PPPC payload. It preserves UUIDs, unrelated payloads, and unknown fields. Rules match by application and receiver identifiers and types.
- `modify` accepts unsigned or CMS-signed profiles but does not verify the signature. Its output is unsigned unless you supply `--sign`.
- Both `generate` and `modify` accept `--sign "Exact certificate name"`. Use `identities` to list available names. Duplicate names cause an error.
- Keychain access can require authorization from macOS.
- File output is atomic and replaces an existing destination. Success returns exit status `0`. Errors go to stderr with exit status `1`.
